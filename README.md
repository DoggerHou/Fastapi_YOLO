# Fastapi_YOLO — детекция людей на снимках с БПЛА

Программный сервис для автоматизированного обнаружения людей на изображениях и видеозаписях с беспилотных летательных аппаратов (БПЛА).  
В основе лежит нейросетевая модель семейства YOLO11, развёрнутая на FastAPI и упакованная в Docker-контейнер с поддержкой GPU.

> Проект реализован в рамках выпускной квалификационной работы.

> В файле `Diploma_presentation.pdf` находится презентация, с которой проект был выдвинут на защиту перед дипломной комиссией

## Назначение

Сервис предназначен для использования в задачах мониторинга и поиска людей в лесных массивах и других природных ландшафтах.  
Классический сценарий: БПЛА снимает местность, оператор загружает кадры / видео в веб-сервис, получает координаты людей и/или размеченные изображения/видео.

---

## Основные возможности

- Приём одиночных изображений через HTTP.
- Детекция людей на изображениях с возвратом координат в формате JSON.
- Возврат размеченного изображения (JPEG) с нарисованными рамками и confidence.
- Возврат результата в виде JSON + base64-изображения.
- Обработка видеофайлов с возвратом видео с визуализацией результатов (MP4/AVI).
- Проверка состояния сервера через health-эндпоинт.
- Автоматическая очистка временных файлов после обработки.
- Документированный REST API с интерактивным Swagger UI (`/docs`).

## Архитектура

Высокоуровневая схема работы сервиса:

1. Пользователь отправляет HTTP-запрос (изображение или видео) на FastAPI-приложение.
2. Приложение валидирует входные данные и временно сохраняет файл (для видео).
3. Файл передаётся в модель YOLO11, развернутую в том же процессе.
4. Результат детекции возвращается:
   - в виде JSON с координатами;
   - или в виде изображения/видео с нарисованными bounding boxes;
   - или в виде JSON + base64-изображение.
5. Временные файлы и служебные директории автоматически удаляются после обработки.

Ключевые компоненты:

- **FastAPI-приложение** — обработка HTTP-запросов и маршрутизация.
- **YOLO-модель** — загрузка весов по пути, указанному в `config.py` (`MODEL_PATH = "yolov_model/best.pt"`).
- **Вычислительный ускоритель** — GPU с поддержкой CUDA (при запуске в соответствующем окружении).
- **Контейнер Docker** — изолированная среда исполнения.

## Модель и данные

### Используемая модель

- Семейство: YOLO11 (Ultralytics)
- Вариант: легковесная модель (аналог `YOLO11s`) с входным разрешением по ширине 1280 пикселей.
- Веса модели: `yolov_model/best.pt` (экспорт по результатам экспериментов из ноутбука `project.ipynb`).
- Задача: детекция людей на снимках с БПЛА (одноклассовый детектор).

### Результаты

Ключевые метрики качества разработанной модели:

- **Валидационная выборка (LaDD)**:
  - Precision: **0.932**
  - Recall: **0.912**
  - mAP@0.5: **0.946**
  - mAP@0.5:0.95: **0.62**
  - Среднее время предсказания: ~**8.3 мс** на изображение (GPU уровня RTX 4070).

- **Тестовая выборка (данные МЧС)**:
  - Precision: **0.785**
  - Recall: **0.634**
  - mAP@0.5: **0.62**
  - mAP@0.5:0.95: **0.281**
  - Среднее время предсказания: ~**8.3 мс**.

Интерпретация:

- На «похожих» на обучающие данных модель обнаруживает >90% людей.
- На новых, «боевых» данных с другим ландшафтом модель всё равно находит ~63% людей, причём ~78.5% всех предсказаний оказываются верными.

## Требования

### Операционная система

- Любая ОС с поддержкой Docker и NVIDIA CUDA.
- Рекомендуется: Ubuntu 22.04 или Windows 10/11.

### Аппаратные требования

- GPU: видеокарта NVIDIA с поддержкой CUDA (рекомендуемая версия CUDA 12.6+).
- Видеопамять: **не менее 3 ГБ VRAM**.
- Оперативная память: **не менее 16 ГБ**.

### Программные требования

- **Для запуска через Docker**:
  - установлен Docker;
  - для GPU — NVIDIA Container Toolkit / поддержка `--gpus all`.

- **Для локального запуска (без Docker)**:
  - Python 3.12.6;
  - возможность установить зависимости из `requirements.txt`:
    - `ultralytics`, `opencv-python`, `pillow`, `numpy`, `python-multipart` и др.

## REST API

Все рабочие методы (кроме служебных) принимают файлы через `multipart/form-data` с полем `file`.  

Общий способ взаимодействия:

- данные передаются через `multipart/form-data`, поле `file`;
- сервис возвращает стандартные HTTP-коды:
  - `200` — успешная обработка;
  - `400` — неверный формат или отсутствие файла;
  - `500` — внутренняя ошибка сервера.

Полный список эндпоинтов, их параметров и форматов запросов/ответов доступен в интерактивной документации Swagger по адресу `http://localhost:8000/docs`:

### Пример для POST запроса `/get_detected_boxes`

- **Назначение:** принять изображение и вернуть список найденных людей в виде JSON.
- **Вход:**
  - `multipart/form-data`
  - `file` — изображение (`image/*`)
- **Выход (200):** JSON

```json
{
  "detections": [
    {
      "x1": 123.0,
      "y1": 456.0,
      "x2": 789.0,
      "y2": 999.0,
      "confidence": 0.87
    }
  ]
}
```
Если людей не нашли:
```
{
  "message": "Объекты не найдены",
  "detections": []
}
```

## Примеры использования

### 1. Через Swagger UI (рекомендуется для ручного тестирования)

1. Запустить сервер (локально или в Docker).
2. Открыть в браузере: `http://localhost:8000/docs`.
3. Выбрать интересующий эндпоинт, например `/get_detected_image`.
4. Нажать **Try it out**, загрузить файл и нажать **Execute**.
5. Результат (картинка / JSON / видео) можно скачать прямо из интерфейса.

### 2. Пример: детекция на изображении (возврат JPEG)

```bash
curl -X POST "http://localhost:8000/get_detected_image" \
  -H "accept: image/jpeg" \
  -H "Content-Type: multipart/form-data" \
  -F "file=@path/to/image.jpg" \
  --output detected.jpg
